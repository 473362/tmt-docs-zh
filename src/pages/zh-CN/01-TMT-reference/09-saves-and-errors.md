# 保存与错误

引擎会将玩家状态和选项一起保存，具体的保存行为如下所述。

引擎还提供了内置错误检测，用于检测损坏的保存数据以及在游戏过程中遇到的错误，具体如下。

## 保存操作

### 保存

“保存”按钮和 Ctrl+S 会将当前状态和选项写入 LocalStorage，并记录当前时间戳。当定期自动保存被禁用时，手动保存仍然有效。在可编辑控件中输入时、打开模态窗口时，或者发生致命错误后，Ctrl+S 将被忽略。

### 自动保存

默认每 `5000` 毫秒保存一次。当禁用自动保存、自动加载出错阻止写入、发生致命错误，或在赢得游戏后暂停前点击“继续游戏”时，自动保存将停止。

引擎还会在 `pagehide` 时尝试保存，条件与自动保存相同。

启动游戏、获胜、“继续游戏”、成功导入、硬重置和选项更改都会立即尝试保存。关闭定期自动保存不会禁用这些即时保存。

### 导出

会打开一个只读的多行提示框，里面包含编码后的保存数据。

恢复导出包括损坏的保存数据。

### 导入

在实际导入前，会验证编码、模组身份、版本、选项、迁移结果和状态。无效的导入不会改变现有游戏和选项，并会在提示框中显示可恢复的错误信息。

成功导入会替换状态和选项，清除临时标签页、深层框架、面板、弹窗和对话框，然后尝试保存。导入的时间戳不会授予离线进度。

### 硬重置

从全新的玩家和层默认开始，清除临时UI状态，保留玩家选项，并尝试立即保存。当 `confirmHardReset` 启用时，引擎会要求确认。

这不会再次调用 `defineMod`、重新运行层设置或创建另一个模拟。层的 `startState` 钩子会运行以创建全新状态。

### 重置选项

将引擎选项恢复到默认设置，并立即尝试保存。

## 玩家选项

这些选项允许玩家控制游戏的运行方式。它们不会受完全重置影响，但会受导入影响。

- `autosaveEnabled` {type: 布尔} {必填}  
允许定时和切换页面时自动保存。默认值为 `true`。
- `autosaveInterval` {type: 数字} {必填}  
自动保存之间的时间间隔，单位为毫秒。必须是 `1` 到 `2147483647` 之间的整数。默认值为 `5000`。设置中输入无效会显示错误。
- `offlineProgressEnabled` {type: 布尔} {必填}  
允许离线进度。默认值为 `true`。
- `hotkeysEnabled` {type: 布尔} {必填}  
允许游戏快捷键。默认值为 `true`。无论如何，快捷键 Ctrl+S 仍然可用。
- `hideCompletedChallenges` {type: 布尔} {必填}  
隐藏已完成的挑战，除非它们处于激活状态。默认值为 `false`。
- `confirmHardReset` {type: 布尔} {必填}  
在界面完全重置游戏前请求确认。默认值为 `true`。

更改选项会验证并更新该选项，然后尝试立即保存。

`EngineOptions` 不是命名的 SDK 导出，且选项并非用于游戏玩法。请使用层状态和表单绑定来实现你自己的游戏玩法设置。

## 保存格式

自动保存使用 LocalStorage 键 `tmt::<mod ID>::save`。保存数据采用 UTF-8 JSON 编码，并以 base64 表示。

解码后的保存数据包含：

- `formatVersion` {type: 数字} {必需}  
引擎保存格式版本。目前固定为 `1`。
- `modId` {type: 字符串} {必需}  
必须与 `info.id` 完全匹配。
- `saveVersion` {type: 数字} {必需}  
模组保存版本。旧版本会触发保存迁移。
- `savedAt` {type: 数字} {必需}  
保存时间戳，单位为毫秒。用于离线进度计算。
- `state` {type: 对象} {必需}  
保存的玩家字段在 `player` 下，保存的层字段在 `layers` 下，以层 ID 为键。
- `options` {type: 对象} {必需}  
上面列出的所有引擎选项值。

### 编码 Decimal

在保存数据中，B_E 数以以下形式表示，以便于检测和重建：

```json
{ "__tmt_decimal__": "1e1000" }
```

## 加载和迁移

加载会读取存储并解码保存的数据。然后，如果需要，会运行一次 `migrateSave(state, fromVersion)`。

缺少的图层、字段和物品会使用游戏默认值。不过，缺少的自定义状态不会自动添加。

例如，将保存的 `settings: { speed: 9 }` 覆盖默认的 `settings: { speed: 1, autoBuy: false }` 时，会保留保存的设置，而不会添加 `autoBuy`。迁移必须显式添加嵌套的默认值。

保存数据中存在但当前游戏中没有的图层或功能 ID 会被拒绝。迁移必须移除或重命名过时的 ID。

只有在解锁且未停用的情况下，保存的活动图层才会保留。否则，加载会按 MOD 顺序选择第一个可用的图层，最后回退到 `info.startLayer`。

最后，成功加载会应用一次离线进度，并尝试以当前时间戳保存。新游戏和加载失败的回退状态不会获得离线进度。更多信息请参见 [Simulation](01/10) 页面。

## 存档恢复

损坏、不受支持或无法迁移的存档会保留原始存档数据不被修改。引擎会创建一个备用状态，显示恢复界面，并阻止普通存档覆盖无法读取的存档。

:::tip 做个贴心玩家
如果你遇到存档恢复，这很可能意味着游戏本身出现了问题。请导出原始存档并联系游戏作者，他们会很感激你的错误报告。
:::

## 致命错误

当触发了游戏挂钩、无效状态或其他任何致命问题时，游戏会暂停并显示错误信息。致命错误界面会显示出错的路径和错误内容，并提供存档导出选项。

:::tip 做个贴心玩家 II
玩家遇到错误（除非你在调试控制台）几乎百分之百意味着游戏自身存在问题。就像存档恢复一样，请导出你的存档并联系游戏作者。不要忘了把错误信息一并提供给他们！
:::
